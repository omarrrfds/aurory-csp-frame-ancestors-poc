How to read the result

  • Served from an origin matching https://*.dev.aurory.io: per Aurory's own Content-Security-Policy: frame-ancestors https://*.dev.aurory.io/ header, the browser permits the frame and the real Aurory UI renders above — the yellow box illustrates where a real decoy button would sit over genuine page content in an actual attack (e.g. over a wallet-approve or purchase-confirm button on a sensitive route).
  • Served from any other origin (this exact file via file://, localhost, or any domain that isn't on the *.dev.aurory.io wildcard): the frame is correctly blocked. Open DevTools → Console to see the browser's own message, which will read approximately: 
    Refused to frame 'https://app.aurory.io/' because it violates the following Content Security Policy directive: "frame-ancestors https://*.dev.aurory.io/".

This file cannot by itself prove that a matching *.dev.aurory.io origin is reachable by an attacker — that would require a separate precondition (e.g. a dangling-DNS subdomain takeover or an XSS on an existing dev host) that has not been tested. What this file does prove, when opened from any origin, is that the policy is real and behaves exactly as the response headers say: same-origin-only framing is not what's actually enforced, despite the X-Frame-Options: SAMEORIGIN header also being present.
